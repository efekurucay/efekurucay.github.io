I Built a Native macOS App to Stop Editing ~/.zshrc by Hand

16 March 2026 · writing · history

I had 40+ terminal aliases in my ~/.zshrc — some broken, some duplicated, most undocumented. Every time I wanted to manage one, I'd open the file in Vim, scroll through hundreds of lines, make the change, and manually run source ~/.zshrc.

So I built Terminal Alias Manager: a native macOS app that gives you a Finder-style interface to manage all your shell aliases. No more raw file editing.

The Problem

Your ~/.zshrc isn't just aliases. It's a mix of exports, PATH configs, plugins, and random snippets accumulated over years. The pain points are real:

  • No way to search or filter aliases
  • Temporarily disabling one means manually commenting it out
  • Moving to a new machine is a copy-paste nightmare
  • Three months later, you have no idea what half of them do

What It Does

Terminal Alias Manager reads your ~/.zshrc, parses every alias, and lets you manage them visually. Key features:

  • Add / Edit / Delete with validation and duplicate detection
  • Enable / Disable by toggling — no manual commenting
  • Search by name, command, or description
  • Auto source — runs source ~/.zshrc after every change
  • JSON import/export for migrating between machines
  • Timestamped backups before any destructive operation

The Core Challenge: Don’t Break .zshrc

The hardest part wasn’t the UI — it was making sure the app never corrupts your existing config. The ZshrcService reads the entire file, strips only the alias lines, preserves everything else exactly as-is, and rewrites a clearly marked block at the end:

# ═══════════════════════════════════════════
# 🚀 Aliases (Managed by AliasManager)
# ═══════════════════════════════════════════
alias gs='git status'
# alias gpo='git push origin'   ← disabled
# ═══════════════════════════════════════════

Disabled aliases are simply commented out — toggle them back on and they’re live instantly.

Tech Stack

Built with Swift 5.9 + SwiftUI, following a clean MVVM architecture. Requires macOS 14.0 (Sonoma) or later. App Sandbox is intentionally disabled since the app needs direct access to ~/.zshrc — it makes no network requests and only ever touches that file.
